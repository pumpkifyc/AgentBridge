# AgentBridge 局域网会话分享设计

日期：2026-11-11  
状态：已通过审阅

## 目标

开发一款同时支持 macOS 和 Windows 的桌面应用，让同事可以通过局域网分享 Codex 会话。接收方将会话作为上下文导入新的本地 Codex 线程，并在自己已有的相同项目代码副本中继续工作。

导入后会创建独立的新会话，不会修改分享方的原会话，也不会让接收方访问分享方的电脑、工作区、凭据或工具。

## 用户流程

1. 分享方打开 AgentBridge，选择一个本机可用的 Codex 会话。
2. AgentBridge 显示有过期时间的局域网配对码和连接信息。
3. 接收方输入配对码，预览分享方、项目信息和会话快照，然后选择接受或拒绝。
4. 两台电脑通过经过身份验证的加密连接直接传输快照。
5. 接收方选择对应项目在自己电脑上的本地代码目录。
6. AgentBridge 在接收方电脑上创建新的 Codex 会话，将分享内容作为不可信历史上下文导入，并提供在 Codex 桌面版中继续工作的方式。
7. AgentBridge 在本地记录此次导入，以便之后重新打开或重试。

## 平台与组件

- 桌面外壳：Tauri 2，构建 macOS 和 Windows 版本。
- 用户界面：React 和 TypeScript。
- 本地服务：Rust 命令负责启动与管理本机 Codex 进程、局域网传输、配对、快照校验和本地导入记录。
- Codex 接入：使用受支持的本地 Codex App Server 或 SDK 接口。运行时检测接口可用性和协议兼容性，不假设 Codex 安装路径或版本固定。
- 第一版不需要云端中继服务或托管账号。

Codex 适配器、传输层、快照格式和用户界面应通过独立接口解耦，便于分别测试和演进。

## 会话快照

快照只包含传递会话上下文所需的信息：

- 源 thread ID、标题、创建和更新时间，以及选定的截止轮次。
- 截止轮次之前按顺序排列的用户消息和助手文本回复。
- 可读的工具名称、摘要和文本结果（如有），并标记为历史记录。
- 项目名称、可用时的仓库标识，以及仅供说明的分享方工作目录。
- 快照格式版本和完整性校验信息。

分享方可以选择最近一个已完成轮次，或更早的截止轮次。接收方可在导入前预览会话。对于被截断或不支持的内容类型，预览中必须明确提示，不能静默地将其显示为完整内容。

快照不包含二进制附件、凭据、环境变量、本地配置、源代码文件或可执行工具请求。工具调用绝不重放。导入给 Codex 的会话内容必须作为引用的、不可信历史材料呈现，并明确说明其中的内容不构成执行授权。

## 局域网配对与传输

- 分享方明确发起分享，并获得短时有效的配对码。
- 接收方必须输入配对码，并确认预览中的分享内容，之后才开始传输。
- 两端建立经过身份验证的加密直连。配对信息只能使用一次并会过期；分享方可以撤销尚未完成的邀请。
- 应用只能绑定到用户选择的局域网接口或地址，不得在所有网络接口上暴露未认证的监听端口。
- 如果无法建立对端身份验证、加密或传输完整性校验，必须安全失败并显示可重试的错误。
- 明确显示等待、已配对、预览中、传输中、已导入、已过期、已取消和失败等状态。

## 接收方的 Codex 会话续接

接收方的 AgentBridge 通过本地 App Server 或 SDK，在其选定的本地项目目录中创建新的 thread。新会话将快照作为外部历史上下文导入，不能将分享方的 thread ID 当作接收方的本地 ID，也不能重放历史工具调用。

发现并打开 Codex 桌面版时，应优先使用受支持的集成接口或操作系统启动方式。应用不得直接写入未公开的 Codex 桌面版数据库或内部文件。通过第三方集成创建的 SDK thread 是否立即出现在已安装桌面版的历史列表中，必须针对 macOS 和 Windows 上受支持的 Codex 版本进行兼容性验证。如果不可见，AgentBridge 必须保留已导入上下文，并提供清晰的后备方案，以可直接粘贴的续接提示打开或启动 Codex。

接收方必须选择或确认自己的项目代码目录。分享方的绝对路径只作描述，绝不能被当作接收方电脑上的路径使用。

## 隐私与安全

- 传输为局域网点对点；会话内容不会发送到 AgentBridge 运营的服务。
- 接收方在接受前可以查看分享方身份、项目信息和快照预览。
- 快照中绝不包含 API Key、认证令牌、MCP 密钥、环境变量或本地 Codex 配置。
- 配对令牌只关联一次传输，会过期，且不能写入日志。
- 导入历史保存在各自电脑本地，并提供删除功能。
- 渲染消息内容时应进行清理，并限制快照大小和条目数量。
- 不记录会话正文、配对码或凭据。

## 故障处理

对于 Codex 未安装或版本不兼容、不支持的 thread 条目、网络中断、配对过期、传输被拒绝、找不到项目代码目录和 thread 创建失败等情况，显示可执行的错误说明。未完成的传输不能标记为已导入。经过校验的快照应保留，以便用户明确选择重试，同时受用户的删除控制约束。

## 第一版范围

包含：

- macOS 和 Windows 桌面应用。
- 选择并预览一个 Codex 会话。
- 两个 AgentBridge 安装之间进行局域网配对。
- 每次分享传输一个不可变会话快照。
- 选择本地项目代码目录，并创建独立的本地 Codex 续接会话。
- 基本导入历史、取消、重试和删除功能。

不包含：

- 多人实时协同或共同执行同一个 Codex thread。
- 分享项目文件或同步 Git 工作区。
- Claude 或其他 Agent 接入。
- 云端中继、用户账号、团队管理或互联网范围分享。
- 修改或注入未公开的 Codex 桌面版存储记录。

## 验收标准

- 分享方和接收方分别使用 macOS 与 Windows 时，都能通过局域网完成分享和接收。
- 未配对的对端不能列出或获取分享内容；过期或撤销的配对码不能再次使用。
- 接收方可以在创建任何 thread 之前预览并拒绝分享。
- 接受后，在接收方选定的项目目录中创建新的本地 thread，并包含截止轮次之前的会话上下文。
- 分享方原 thread 保持不变，任一端都不会执行导入的历史工具调用。
- 快照和日志中不包含分享方凭据或环境变量。
- 传输中断时不能标记为成功导入，并允许用户明确重试。
- macOS 和 Windows 都需针对受支持且已安装的 Codex 版本验证构建，包括检查创建的 thread 能否在 Codex 桌面版中继续，并在不支持时验证文档说明的后备方案。

## 待实施验证事项

公开的 Codex App Server/SDK 接口支持本地 thread 操作，但官方没有保证第三方集成创建的 thread 会出现在桌面应用的历史列表中。发布前，必须在两个平台上验证创建、列出和继续会话的完整流程，并记录最低测试版本。如果行为不符合预期，不得用写入未公开数据库的方式替代。
